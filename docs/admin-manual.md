# 本部管理者（admin）向け操作マニュアル

合同会社絆 福祉施設管理SaaS（welfare-manager-app）

本部管理者（admin）は、契約中の全事業所を一元管理する役割を持ちます。本マニュアルでは、ログインから各画面の操作までを解説します。

---

## 0. 前提

- **本番URL:** https://welfare-manager-app.vercel.app
- **ログインURL:** https://welfare-manager-app.vercel.app/login
- **対象ロール:** `admin`（本部管理者）
  - `facility_admin`（事業所長）・`facility`（施設スタッフ）は別画面（`/facility/*` / `/`）
- **推奨ブラウザ:** Google Chrome / Microsoft Edge（最新版）
- **必要権限:** Supabase の `profiles` テーブルで `role = 'admin'` が設定されたユーザー

---

## 1. ログイン

1. `/login` にアクセス
2. メールアドレス・パスワードを入力
3. ログイン成功後、自動的に `/admin` （SaaS管理画面）にリダイレクト

> admin 以外のロールでログインした場合、`/admin/*` 配下にはアクセスできません（proxy ミドルウェアで保護）。

## 3. 各画面の操作

### 3.1 SaaS管理（`/admin`）

**目的:** 全契約事業所の稼働状況を俯瞰する。

- **サマリーカード**
  - 契約事業所数 / 今月稼働中 / 未稼働 / 今月の日報合計
- **事業所一覧テーブル**
  - 事業所名・事業種別・登録日・今月の日報件数・稼働状況
  - 「未稼働」（今月の日報件数が0件）の事業所はフォローアップ対象

> **運用ヒント:** 毎週月曜にこの画面を確認し、未稼働の事業所には LINE 通知または電話でフォローを入れます。

---

### 3.2 事業所管理（`/facilities`）

**目的:** 新規事業所を登録し、初期管理者アカウントを発行する。

**新規事業所の登録手順:**
1. 「新規事業所追加」フォームに事業所名・事業種別を入力
2. 初期管理者用のメール・パスワードを入力
3. 「登録」ボタンを押すと、内部で `/api/create-facility` が走り、Supabase Auth ユーザー + `profiles`（`facility_admin` ロール）+ `facilities` レコードを同時作成
4. 登録完了後、事業所長にメール・パスワードを連絡

**事業種別:** `生活介護`・`就労継続支援B型`・`放課後等デイサービス` など（`SERVICE_TYPE_LABELS` 参照）

---

### 3.3 利用者管理（`/clients`）

**目的:** 全事業所の利用者マスタを横断的に管理する。

- **追加:** 「利用者追加」ボタン → 氏名・所属事業所・ステータス・メモを入力
- **編集:** 行の鉛筆アイコンから編集
- **削除:** ゴミ箱アイコン（要確認）
- **ステータス:** `利用中` / `休止中` / `退所`

> **注意:** 退所した利用者を削除すると過去の日報との関連が切れます。原則「退所」ステータスで残してください。

---

### 3.4 施設ダッシュボード（`/dashboard`）

**目的:** 運営指導対応・監査準備のタスクを管理する。

- カテゴリ別にタスクを追加
- 期日が近いタスクは強調表示
- チェックで完了

> **前提:** `tasks` テーブルのマイグレーション（`20260427_tasks.sql`）が実行されていること。

---

### 3.5 出欠入力（`/attendance`）

**目的:** 利用者ごとの日々の出欠を記録する（加算計算の基礎データ）。

- **出欠:** ○ 出席 / △ 遅刻・早退 / ● 欠席
- **食事:** ○ あり / ● なし
- **送迎:** ○ あり / ● なし（行き・帰りそれぞれ）

「保存」を押すまでDBに反映されない点に注意。

---

### 3.6 シフト管理（`/shifts`）

**目的:** スタッフのシフトをCSVから一括取込し、日報の自動補完に利用する。

**取込手順:**
1. CSVを準備（列名: `日付` / `氏名` / `役職` / `シフト種別` / `開始時刻` / `終了時刻`）
2. 「CSVアップロード」からファイル選択
3. プレビュー確認 → 「取込実行」
4. 取込済みシフトは下部一覧に表示。不要な行はゴミ箱で削除可

> 日報入力時、当日勤務スタッフが自動で候補として表示されます。

---

### 3.7 入力状況（`/status`）

**目的:** 日報が滞っている利用者をアラートで可視化する（**監査リスク管理の中核画面**）。

- **OK:** 1日以内に入力あり
- **要注意:** 2〜3日入力なし
- **危険:** 4日以上入力なし
- **未入力:** 一度も入力なし

「就労」「生活」の2系統で別々に判定されます。

---

### 3.8 個別支援計画（`/support-plans`）

**目的:** 利用者ごとの個別支援計画書を作成・改訂・Excel出力する。

- **新規作成:** 利用者を選び、AIドラフト生成（前回計画＋直近日報から自動下書き）
- **改訂:** 既存計画から「改訂版」を作成（version が自動インクリメント）
- **Excel出力:** クライアント様式に合わせたテンプレートで `.xlsx` 出力

> 6ヶ月ごとの改訂が法定義務。`plan_end_date` が近い計画には注意。

---

### 3.9 モニタリング評価（`/monitoring`）

**目的:** AIが直近の日報を要約し、モニタリング記録票を自動生成する。

1. 利用者を選択
2. 評価期間を指定
3. 「AI評価生成」ボタン → Gemini API が日報を読み込み、達成状況・課題・次期目標を出力
4. 内容を確認し、Excel出力

---

### 3.10 加算・請求集計（`/billing-report`）

**目的:** 月次の加算項目を集計し、請求書を出力する。

- 出欠・送迎・食事の記録から自動集計
- 国保連請求形式で出力（PDF/CSV）

---

### 3.11 帳票自動生成（`/documents/generate`）

**目的:** 法定書類（契約書・重要事項説明書・サービス提供記録など）を自動生成する。

- 利用者情報を埋め込んだ書類を PDF/Excel で出力
- Supabase Storage の `welfare-docs` バケットに保存される

> **前提:** Storage バケット `welfare-docs` が作成済みであること。

---

### 3.12 プラン・課金（`/billing`）

**目的:** 契約プランを表示し、Stripe Checkout への導線を提供する。

| プラン | 月額 | 含まれる機能 |
|---|---|---|
| ライト | ¥5,000 | 運営指導チェックリスト、書類保管庫、基本通知 |
| スタンダード（推奨） | ¥12,000 | ライト + AIモニタリング、日報入力アプリ、PDF出力 |
| プレミアム | ¥20,000 | スタンダード + LINE通知、優先サポート、監査対策レポート |

> **前提:** Stripe の price ID が環境変数に設定済みであること（`STRIPE_PRICE_LIGHT` 等）。

## 5. よくあるトラブル

### Q. ログインしても `/admin` に飛ばずに `/` に飛ぶ
A. `profiles.role` が `admin` になっていません。Supabase SQL Editor で確認:
```sql
SELECT id, email, role FROM profiles WHERE email = 'your@email.com';
```
`admin` 以外なら更新:
```sql
UPDATE profiles SET role = 'admin' WHERE id = 'UUID';
```

### Q. ダッシュボードが真っ白
A. `tasks` テーブルが未作成です。`supabase/migrations/20260427_tasks.sql` を Supabase SQL Editor で実行してください。

### Q. 帳票生成でエラー
A. Supabase Storage の `welfare-docs` バケットが未作成です。Dashboard → Storage → New Bucket（Private）で作成してください。

### Q. 「事業所が登録されていません」
A. 初期状態です。`/facilities` から1件目を追加してください。
